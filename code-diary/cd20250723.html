代码日记 - 2025年7月23日 Thu

枚举总复习

把3年内的面试题收集到spreadsheet中，并分类，命名（唯一ID 公司代码-问题序号） 唯一的命名相当于JIRA卡片Id，方便后续算复习百分比，画燃尽图，按照艾宾浩斯遗忘曲线循环安排复习。 全部面试题都要消灭，复习到，我能拿一支笔一张纸，按图索骥一图流，一口气画出所有面试题的考点和答案。就像准备标准化考试一样。 不能每次面试都撞大运。面试撞大运，是可耻的。 消灭完我面过的题，立刻海投+内推+私信过去联系过的HR，安排面试。

统计总复习时我发现，有3家面试我录下了全程，但是因为自觉糟糕，我竟然拖着没有及时复盘。

xlookup 小技巧 句柄下拉不灵怎么办？

csrf 攻击防范我并没有真正理解如何做。

TDD 的练习我放弃了读书，直接在闲鱼买了极客时间的周卡，看八叉的课程，直接上手。 书上的例子和生产级的代码差别太远了

routine 感想

作息越来越混乱，不是好事。 三分化推拉腿，逐渐养成习惯了，坚持下去。我要建立起如同“到点该吃饭”一样强的念头，在”到点该锻炼“上。

任何时候，都要用git提交变更。因为 git log可以作为llm的输入自动生成周报。

算法题、英语，两项复习要抓紧。 AI 帮我打算法题草稿，提示词如下： 使用 ascii 字符画，分步描述你设计的算法对链表的操作，以便我能更直观地理解，图示的测试用例：head = [1,4,3,2,5,2], x = 3 这样的ascii图示，比我自己以便单步调试，以便手画要方便得多。 手画一开始我以为印象深，但实际上我发现手画的第二次还是忘得一干二净。切手画不容易快速看到big picture，大部分经历耗散在盯着变量赋值。 高效地得到图示，然后理解到数据结构的操作，然后仿写代码，尽快通过题目。 然后随着遗忘曲线安排重复，才是强化的正道。 不要寄希望“我一次做得非常细致，一口气记住，然后就再也不用管”。 算法题本质上是模式识别，准备算法题本质上在做两件事：1、理解记住模板；2、对抗遗忘。（如果不算记住语言和包的Api的话）

对过去项目的理解尚不够透彻，参考总复习的面试题，可以结构化地拆解项目要害： ，技术栈，你负责的部分。 项目对应的是什么业务 数据量是多少？ 项目的复杂度在哪里 项目难点的在业务难点还是技术难点？ 访问控制/鉴权体系如何实现 对接了其他系统，你具体在对接过程中做了什么。 业务如何实现系统间调用 做这个项目有什么收获吗？ 能总结一下开发经验吗？它有什么通用性吗？ 你这个经验能解决哪一类的问题？ 有没有一个场景，发现一个故障，来张从如何去发现的，到如何去解决的

另外，每一个项目还应该有一个“时间线time line”，让我清醒，每一个项目起止时间，做了多久，有哪些里程碑。 这是受到了 如何评价 Trae 发布 2.0，以及新推出的 SOLO 模式体验如何？ - 天猪的回答 - 知乎 https://www.zhihu.com/question/1930712114894431572/answer/1930973959412753056 的启发。 “知道自做了什么，还差什么没做，未来还能做什么” 才能锻炼tasking 。 否则只能稀里糊涂，走一步退三步。

公开课攒了很多，在总复习和算法、英语准备完成之后，再考虑刷课。

InfiniTensor 2025夏季的课可以放直播黑听，但是首先以准备面试为重。
