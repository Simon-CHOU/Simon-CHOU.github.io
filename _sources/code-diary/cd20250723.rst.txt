routine 感想
--------------------
作息越来越混乱，不是好事。
三分化推拉腿，逐渐养成习惯了，坚持下去。我要建立起如同“到点该吃饭”一样强的念头，在”到点该锻炼“上。

任何时候，都要用git提交变更。因为 git log可以作为llm的输入自动生成周报。

算法题、英语，两项复习要抓紧。
AI 帮我打算法题草稿，提示词如下：
使用 ascii 字符画，分步描述你设计的算法对链表的操作，以便我能更直观地理解，图示的测试用例：head = [1,4,3,2,5,2], x = 3
这样的ascii图示，比我自己以便单步调试，以便手画要方便得多。
手画一开始我以为印象深，但实际上我发现手画的第二次还是忘得一干二净。切手画不容易快速看到big picture，大部分经历耗散在盯着变量赋值。
高效地得到图示，然后理解到数据结构的操作，然后仿写代码，尽快通过题目。
然后随着遗忘曲线安排重复，才是强化的正道。
不要寄希望“我一次做得非常细致，一口气记住，然后就再也不用管”。
算法题本质上是模式识别，准备算法题本质上在做两件事：1、理解记住模板；2、对抗遗忘。（如果不算记住语言和包的Api的话）

对过去项目的理解尚不够透彻，参考总复习的面试题，可以结构化地拆解项目要害：
，技术栈，你负责的部分。
项目对应的是什么业务
数据量是多少？
项目的复杂度在哪里
项目难点的在业务难点还是技术难点？
访问控制/鉴权体系如何实现
对接了其他系统，你具体在对接过程中做了什么。
业务如何实现系统间调用
做这个项目有什么收获吗？
能总结一下开发经验吗？它有什么通用性吗？
你这个经验能解决哪一类的问题？
有没有一个场景，发现一个故障，来张从如何去发现的，到如何去解决的

另外，每一个项目还应该有一个“时间线time line"，让我清醒，每一个项目起止时间，做了多久，有哪些里程碑。
